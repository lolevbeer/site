## Deployment requirements

Run the appended migrations before accepting public intake with the new code. The submissionKey indexes are unique and sparse, so existing records without keys remain valid. Past exact duplicates are not retrospectively removed. Reservation expiry checks do not depend on Mongo's asynchronous TTL cleanup.

Submission identity is the entire normalized persisted form content, excluding the IP hash. Identical content is acknowledged as the same stored submission for as long as that record exists; changed content remains distinct. The old per-process email throttle is removed; distributed IP capacity remains three submissions per form per rolling hour. A failed persistence attempt releases its reservation. A crashed writer can retain one slot until it expires, conservatively reducing capacity.

The new cron cadence requires a Vercel plan that supports it and deployment of `vercel.json`. Daily task scheduling remains 06:00 UTC. Eligible retries run on a later five-minute invocation; backlog and platform delay may add latency. No production cron setting was changed in this work.

Distributor imports trust Encompass8-owned hostnames. Redirects are rejected even between approved hosts. Check both configured QuickLinks through an authorized preview import before release; this work has not fetched production links or geocoded stores.

## #257: concrete enforcement proposal, approval pending

`main-ruleset-proposal.json` is a proposed GitHub ruleset, not an applied setting. On October 5, read-only GitHub inspection found no ruleset/classic protection for main. The current successful main commit publishes `checks` and `release-smoke` through GitHub Actions app 15368; those exact contexts are in the proposal.

The proposal requires PRs, both successful checks on an up-to-date branch, resolved review threads, and blocks deletion/force pushes. It requires zero approvals so a sole maintainer can merge their own tested PR. There is no routine bypass actor. A repository admin must approve that policy before applying the file with the GitHub ruleset API. Test on a disposable branch/ruleset with a deliberately failing check, then verify blocked merge/direct-push and a successful PR. Do not deliberately break main to test it.

Emergency recovery: a named repository admin can temporarily change enforcement to evaluate/disabled, record the incident and exact reason, then restore active enforcement and verify contexts immediately after recovery. No bypass credentials or app permissions are added by this proposal.
